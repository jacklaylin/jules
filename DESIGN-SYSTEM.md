# Jules web design system

The current visual system adapts the founder-supplied [brief](docs/design-system/BRIEF.md) and [original tokens](docs/design-system/tokens.css) to the existing plain HTML/JavaScript app. The attached brief supplies visual guidance, not permission to build future screens or change supported shopping behavior.

## Scope and ownership

- `public/design-system.css` owns shared tokens, local fonts, typography, full-width gutters, header, controls, selection chips, focus states, dialog defaults and reduced-motion/forced-color behavior.
- `public/design-system.js` mounts the companion-page header once and preserves sign-out and the permission-controlled Admin link. Pages attach their own actions.
- `public/brand-ui.js` supplies the shared outlined wordmark, orb dot, request-driven thinking/completion states and favicon controller. SVG outlines come from the locally licensed Instrument Serif; the logo never depends on a fallback dotless-j glyph.
- `public/brand-mark.js` paints the same outlines and a frozen orb into PNG exports. `public/brand/` contains the wordmark and font-independent favicon frames.
- Page CSS owns composition only. Repeated controls belong in the shared layer; base control selectors have low specificity so explicit page compositions such as image overlays retain their positioning.
- `public/admin-console.js` mounts the owner console on every admin page: the standard companion header (via `mountHeader('admin')`, so Admin is the current page and Log out signs out of admin), a slim 40px strip of tool links under the header (current one underlined; it stays under the compact header, scrolls sideways on phones at 44px and leaves tables the full width), and the single owner sign-in. Its styles are the admin-console section of `design-system.css`, followed by the shared admin data components from the October 14 design handoff (status badges in tinted green/amber/red, each with a glyph and a word; tabs; filter chips with counts; data tables; stats; folds; notice bars; `.confirm-dialog`, the owner confirmation that lists exactly what an action removes and keeps); admin page CSS owns composition only.
- **Data view** (admin table pattern, design in `design/admin-table-pattern-handoff.md`): every admin table page uses, top to bottom, optional views (`.dv-views`, quiet pills for a tab's sub-pages, linkable with `?view=`), one toolbar row (`.dv-toolbar`: status filter as a segmented `.seg` with counts, `.dv-search` with a `/` hint, a Filters menu and at most one butter primary action), one status line (`.dv-status`, with removable `.dv-token` filters and the Aqua `.dv-loader` only while something runs), dense 40px rows (`.dv-list`, `.dv-head`, `.dv-row`; the page sets `--dv-cols`) and a detail panel beside the list (`.dv-split.open` + `.dv-detail`; on phones the detail takes the screen). A page has one More menu (`.dv-menu`, at the right of the page header): the same actions on every tab, grouped by area, and an action that belongs to a tab opens that tab first; never a second ⋯ menu. Menus are `.dv-pop` popovers (`.dv-menu`, `.dv-filters`) positioned under their button by `anchorMenus()` from `admin-console.js`. Keys: `/` search, J/K move rows, Enter opens, Esc closes. Editable tables (inputs and actions in cells) use a real `.dv-table` with the same dense look, and `button.quiet` for low-weight row actions. **Calm admin:** one navigation layer per level, serif titles and sans everything else (no mono caps in admin), one coloured button per screen (`button.quiet` for every other control), views as plain text links, the status filter as the only pill group, and a Note column that shows exceptions instead of repeating defaults (no source when there is one, no "For them"). Keyboard hints appear once, beside the action they speed up. A page title above a data view is `.dv-title` (34px serif); a row of headline figures is one bordered `.dv-metrics` strip of `.dv-metric` cells (label, value, verdict badge; a `.dv-metric-label` cell first; two columns on phones). A figure beside the title (a day's total) uses `.dv-heading` with a `.dv-heading-note`; a labelled toolbar input (a day picker) is `.dv-field`; quiet footnotes under a table are `.dv-note`. Purchase history, Personal memory, People and Costs use it.

## Visual rules

White page ground; neutral product-image surfaces. Ink `#17120F`, fog `#F3F1EE`, line `#E8E4E0`, secondary text `#6B625B`. Butter is the primary-action color; grape is for sharing and focus. Tangerine, bubblegum and grape form the orb. Aqua is reserved for iMessage bubbles and the indeterminate loader.

Hairlines and card borders use `line`; text inputs, selects, textareas and `.field` use `line-strong` `#8A817A` (3.8:1, meets the 3:1 control-boundary rule). Every colour shared CSS paints is a `:root` token, including the orb glow, gel gloss, Aqua loader parts (`aqua-*`), iMessage details (`imsg-*`), `photo-overlay`, `backdrop` and the `shadow-dialog`/`shadow-panel` shadows. Page CSS reuses tokens rather than writing hex values.

Errors use `danger` `#B42318` (6.6:1) and always say in words what failed and the next step. An invalid field gets `aria-invalid="true"` (2px danger border) with a `p.error` message beneath it; a failed page or section uses a `.notice--error` box. Partial results stay visible.

Buttons are coloured by class only: `btn--butter` for the primary action, `btn--grape` for sharing, `btn--ink` for dark actions. Bare `<button>` elements get the white gel pill through a zero-specificity `:where()` rule. Shared CSS never targets page IDs or a page-level `.primary` class for button colour.

Wishlist photos use contain sizing to keep the full saved image visible in cards, retailer previews and the detail carousel. Loaded frames match a consistent image-edge background color; varied or unreadable edges fall back to white. Loading and unavailable-photo surfaces retain fog. Photos are never tinted, stretched or generated to fill the frame.

Instrument Serif roman supplies headlines; Bricolage Grotesque supplies body text and bold starter-pack titles; JetBrains Mono supplies small labels/data. All fonts and redistribution licenses are bundled in `public/fonts/`; no external font request or CSP expansion is required. The old Mongule/neon wordmark, random hover gradients and rotating display-font pool are no longer used by these pages.

Collection pages share their pieces through `design-system.css`, not page stylesheets: the `.collection-heading` title (large serif title with the item count opposite, count beneath on phones, with `.heading-desktop`/`.heading-mobile` label swaps), the `.product-grid` of `.product-card` tiles (`.tile`, `.photo`, `.card-price`, `.card-state`, `.photo-pending`, skeletons), the round `.icon-button` photo controls (`.remove-item` upper-left, `.alert-toggle` upper-right) and the `.toast`. A new collection page, such as the wardrobe, reuses these classes rather than restyling cards. Photo frames cast no shadow.

Actions use one gel-pill vocabulary with 44px minimum targets. Selected radio chips retain native inputs. Wishlist chooses its desktop column count from the available width, using a 280px minimum card width and a maximum of four columns, and uses two on phones, with equal-height rounded cards, portrait image slots, bold product titles and mono price labels. Photo-pending slots use the orb and an honest status label. The alert bell remains at the upper-right, with ink on butter and an ON badge when active. Removal is available on each card at the upper-left, with an accessible label and undo; the alert stays at the upper-right. Product details use the same saved product title and have no refresh or removal controls. Saved metadata renders before background photo recovery; opening a product shows its known summary immediately. Desktop heading is Wishlist; mobile heading is Your wishlist with the count beneath. Shared dialogs use rounded borders, visible focus and keyboard support. Main/header align to `--page-gutter` (5vw), without a centered outer max-width wrapper.

The header retains a compact scroll state without shifting body spacing. Desktop shows serif Wishlist, Wardrobe, Your style, permission-controlled Admin, and Log out links, each section colour-coded with one Jules colour (Wishlist butter, Wardrobe tangerine, Your style bubblegum, Admin grape): a 4px bar grows from the centre under the label on hover/focus and stays under the current page. Labels stay ink/`text-2`, the bar is drawn under the text so nothing shifts, and the orb is not used as a nav marker. At 800px and below, a gel Menu button opens a full-screen white modal with the same navigation nodes in a vertical list; the current page keeps its 6px colour bar. Escape/Close restores focus and page scrolling; resizing to desktop closes the menu. Admin-link permissions and logout handlers remain attached to the same elements. The last header item is the **Account** avatar (`.nav-account`): a 38px fog circle with a person outline in the desktop bar, grape-bordered on hover and on `/account`. In the phone menu it becomes a labelled "Account" row with a larger avatar. The menu footer reports the actual wishlist count when available and is cleared on sign-out.

### One pill, then quiet rows (secondary actions)

A screen that ends with several next steps uses one coloured gel pill for the single most useful action, then lists the rest as quiet rows (founder, October 16, 2026; first used on the style report end screen). Don't stack several equal-weight pills or split secondary actions into half-width pills.

- **Primary:** one full-width gel pill, 56px tall. Grape when the action is sharing, butter otherwise. If a prerequisite is missing (for example an unlinked order source), that prerequisite takes the pill and the usual primary drops into the rows.
- **Rows:** full width, at least 56px tall (48px on screens under 640px tall, still above the 44px touch minimum), separated by 1px `line` hairlines with one above the first row. Each row is a 22px icon, a 12px (`space-3`) gap, the label in Bricolage 600 16px `ink`, and an optional `text-2` "↗" at the far end when the row leaves the page (Messages, another site). No pill, fill, gloss or shadow; hover turns the label grape on fine pointers; focus is the grape ring drawn inside the row.
- **Shared classes:** `.action-rows` (the container, with the hairline above the first row) holding `.action-row` buttons or links; a `.action-row__go` span carries the end mark ("↗" or "→"). Onboarding's connect screen uses them; the style report end screen still has its own copy.
- **Leaving:** Exit or Close is a 44px round × button in the top-right corner (1px `line` border on white), not a row or a text link. On the desktop stage the window's own close button replaces it.
- **Icons:** line icons on a 24px grid, 1.8px stroke in `currentColor`, round caps and joins, no fill, `aria-hidden` beside a visible label. Current set: share (arrow out of a tray), link (two chain links), chat (speech bubble), replay (circular arrow) and close (×, 2px stroke). Draw a new icon in the same style rather than adding an icon set or emoji.

On dark grounds (the desktop story stage) the same hierarchy holds: Share is the one filled grape gel pill, and the other controls (thumbs, Edit lines, Shuffle, close, arrows) are quiet outlines, a 1.5px white border at 35% opacity over a 5% white fill. A pressed thumb fills with butter.

## Activity and motion

`public/activity.js` tracks concurrent requests and local workflows. It shows the actual current action and that action's elapsed time. The orb and Aqua loader replace the old spinner. Private image fetches retain neutral per-image placeholders without flashing the page activity panel.

Only explicit style analysis and shopping-chat POST operations trigger the header dot hop and favicon frames. Loading pages or saving notes does not imply a store search. Other agent workflows can explicitly pass `{agent:true}` to `withActivity`. HTTP errors and thrown failures suppress successful completion for that activity batch. The next batch can recover normally.

The orb spins in 7s and wobbles in 4s. Thinking hops in an 8s loop, with horizontal distances calibrated to the outlined letters and a smaller return arc inside compact headers; successful completion has a short landing pop. Favicon frames swap every 350ms and settle to the static icon. Hidden tabs stop favicon intervals. Reduced motion disables all decorative animation, including typing, entrances, hover transitions and favicon swaps, while retaining readable status text. The Aqua capsule is indeterminate and never represents measured progress.

The test chat retains real simulator behavior with native iMessage fonts/colors, last-in-group bubble tails, photo bubbles and typing feedback while a request runs. Previously rendered messages do not replay their entrance on every update.

## Deferred

New feed screens, new nine-cell starter-pack layouts, additional Wrapped moments, animated marquee placement and navigation to unbuilt destinations. Never ship the brief's example prices, stock, store counts, style-match percentages, wear counts, delivery or purchasing claims as facts.

## Public landing page

The public `/` page is a single-screen layout with an autoplaying iMessage demonstration. Each page load plays one conversation chosen at random (Satisfy x HOKA sneakers, or a Balenciaga Rodeo resale-vs-dupe search); the end shows Replay and Shuffle topic, which always switches to a different conversation, with responsive composition in `public/landing.css`. `public/landing-timeline.js` holds each conversation’s duration and typing windows and supplies deterministic progress and typing states; typing windows must end exactly when the matching Jules message appears in `index.html` (tested). Bubbles retain their full 450ms sender-corner entrance; typing indicators precede Jules replies, and the chat scrolls to new messages over 700ms. Autoplay starts on load; page scrolling does not drive the demo. Reduced motion displays the complete chosen conversation, with Shuffle topic but no Replay; an inline screen-reader transcript is also available without JavaScript. The example conversations are labeled illustrative; their listing prices were captured from real listings and will drift.

`mountPublicHeader` in the shared JavaScript hydrates public-page logos, while the shared gel links and header navigation primitives serve `/`, `/signup` and `/login`. Public signup collects private consent records only; outbound welcome messages are not enabled. See `LANDING-PAGE.md` for setup and remaining launch requirements.

## Verification before shared changes ship

Check wishlist and style at desktop, 390px and 320px phone widths, including logo rest/hover/thinking/completion, compact header, signed-out forms, uploads, draft review, confirmed cards, image controls, product/alert/evidence/export dialogs, long copy, PNG output, keyboard focus and no horizontal overflow. Check reduced motion, HTTP failures, concurrent request completion, and browser errors. Also smoke-check simulator and owner screens. Use synthetic browser fixtures; do not send real messages or perform paid searches just to verify styling. Run the application suite when shared JavaScript changes.
